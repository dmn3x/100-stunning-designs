# MiniMax M3 — Gallery Index Polish (apply after 100 designs exist)

Source root: `MiniMax M3/`. Build brand-new file: `MiniMax M3/index.html`. Self-contained, no external URLs/assets, no frameworks, no build step.

## Goals
- Make the gallery feel like a curated editorial *publication*, not a grid of tiles.
- Surface the *substance* of each design (palette, motion, interaction, layout) so the page itself is the showpiece.
- Match the project's existing tone: artistic, technical, restrained, no SaaS cliches.

## Structural Direction (pick ONE, do not blend)
- **Editorial Almanac** (recommended): hero masthead "MiniMax M3 — 100 Studies in Stunning", numbered "Spreads 01–100" laid out as a magazine back-of-book with asymmetric columns. Each spread reveals palette swatches, motion glyphs, and a two-line synopsis that varies sentence rhythm (declarative / interrogative / fragment). Filter chips at the top: All · Spreads · Color · Motion · Editorial · Interaction · Canvas · Type. Filter changes reflow the list, no navigation reload. Footer is a "Colophon" block: process, license, content warning that pages can flash/strobe, link back to root README.
- Orbit Atlas (alternative): if the agent already shipped an editorial version, replace with a circular SVG map; each design is a planet with a distinct orbit color and a one-line tagline. Hovering a planet shows its synopsis in a fixed panel; clicking opens the design. Filter chips behave as zoom modes.

Do NOT keep a flat 10×10 tile grid. Do NOT auto-embed iframes of every page; thumbnails are tiny CSS-rendered chips that hint at the design's identity.

## Visual language
- Serif display headline (system serif stack, no remote fonts) paired with mono for indices/numbers.
- Paper off-white background (#f6f1e7) by default; dark mode toggle via `prefers-color-scheme` plus a manual switch persisted in localStorage.
- Palette swatches per entry are CSS-rendered inline chips generated from each design's dominant CSS color tokens (do NOT scrape files — pick from a curated 12-token palette per entry in the data list).
- Motion: subtle reveal on intersection; `prefers-reduced-motion: reduce` cancels transitions.
- Single subtle accent rule (1px) under headings; nothing purple-gradient, nothing glassmorphic by default.

## Data shape (hand-written inline JSON, lazy-senior style)
```html
<script id="entries" type="application/json">
[
  {"n":1,"slug":"01-paper-moon-observatory","title":"Paper Moon Observatory","palette":["#0e0b1f","#f7e7c1","#7aa2c4"],"tags":["editorial","type"]},
  ...
]
</script>
```
Keep it flat; do NOT architect a JS module system.

## Interactions
- Filter chips: pure client-side filter over the array; no URL hashes required.
- "Open" link per entry opens the design in a new tab (`target="_blank" rel="noopener"`).
- Keyboard: `Tab` cycles filter chips then entries; `Enter` opens focused entry.
- Colophon copy includes a credit line "Generated by MiniMax M3 via Hermes Agent" and a link back to the root README.

## Acceptance
- Same self-contained rules as the 100 designs (no external URLs, no libs).
- HTML/CSS/JS lints clean of remote URLs and bare `<link>`/`<script src=http...>`.
- Renders correctly at narrow viewport (single column) and at desktop (asymmetric multi-column).
- README update is still required (same instruction as the build plan).
